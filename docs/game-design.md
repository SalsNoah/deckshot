# DECKSHOT（デックショット）ゲーム骨子

> **3分で決着する、読み合いFPSカードバトル。**
> 撃ち合いは「先に撃ったほうが勝つ」。スモークを焚き、フラッシュを投げ、裏を取り、C4を仕掛ける。キルを重ねたら、最後は戦術核。

## 1. コンセプト

| 項目 | 内容 |
| --- | --- |
| ジャンル | 1vs1 同時ターン制 対戦カードゲーム（PvP / CPU戦） |
| ターゲット | 10〜20代男性。VALORANT / Apex / CoD / CS を遊んでいる、または動画で見ている層 |
| プラットフォーム | スマホ（縦画面）。開発中はWeb（PWA）で動かし、Capacitor で iOS/Android に出す |
| 1試合 | 6〜9ターン、約4〜6分 |
| 体験の核 | ①同時公開の読み合い（"ピーク"の読み合い）②AIMの速さで決まる撃ち合い ③キルストリークで逆転／トドメ |

### 面白さの柱

1. **読み合い = FPSのピーク**
   両者が同時に作戦を立て、同時に公開する。「相手はBを詰めてくる」「いや、スモークを焚いてミッドに回るはず」という、FPSで角を覗くときと同じ緊張感を作る。
2. **撃ち合いはAIM順**
   全オペレーターが AIM の高い順に撃つ。先に撃たれて倒れたユニットは撃ち返せない。AIMが同じなら同時に撃つので相討ちになる。フラッシュでAIMを0にする、裏取りで一時的にAIMを上げる、といった**FPSのセオリーがそのまま強い**。
3. **経済（エコ）**
   クレジットは使い切らなければ次のターンに持ち越せる。キル報酬とロスボーナスもある。余ったクレジットは**補給**でカードに換えられるので、「今カードを出すか、補給して次に備えるか」という判断が最後まで続く。
4. **キルストリーク**
   キルでSP（ストリークポイント）が貯まり、味方がやられたターンにも少し貯まる。UAV → 空爆 → **戦術核（予告から1ターン後に着弾して勝利）**。溜めるか使うかのジレンマが生まれ、「核を止めろ」という最大の読み合いターンが見せ場になる。
5. **気持ちいい演出**
   満タンのHPから一撃で倒すと **HEADSHOT**。同じターンに複数キルを取ると **DOUBLE/TRIPLE KILL**、相手を全滅させると **ACE**。キルフィードも流れる。

## 2. ルール

### 2.1 盤面
- ゾーンは **A / MID / B** の3つ。各プレイヤーは1ゾーンに最大3体までオペレーターを置ける。
- ゾーンにはそれぞれ**ゾーン効果**がつく。試合ごとに11種類の中からランダムで3つ選ばれる（例: 高台＝支配すると2pt）。

### 2.2 勝利条件（ドミネーション）
- ターン終了時に、あるゾーンに**自分のオペレーターだけ**がいれば、そのゾーンを**支配**して **+1pt**（高台は2pt）。**7ターン目以降は支配点が2倍**。
- **マッチポイント**: ターン開始時に相手が8pt以上で自分が負けていれば、自分が支配したゾーン1つにつき +1pt。
- **先に 10pt** 取ったプレイヤーの勝ち。同じターンに両者が10pt以上になったら、点数の高いほうが勝つ。同点なら決着がつくまで延長する。
- 10ターン目が終わった時点で決着していなければ、点数が高いほうが勝つ。同点ならキル数で決め、それも同じなら引き分け。
- **戦術核**は、起動した次のターンの終了時に着弾して勝利する。その時点で相手が2ゾーン以上を支配していれば阻止される。

### 2.3 ターンの流れ
1. **作戦フェーズ（同時・非公開）**: 以下の行動を、クレジットの許す限り自由に組み合わせる。
   - オペレーターを出す（ゾーンを指定）
   - 装備を付ける（自分のオペレーターに。このターンに出したオペレーターにも付けられる）
   - 戦術を使う（ゾーン、または敵・味方のユニットを対象にする）
   - ローテ（前のターンからいるオペレーターを隣のゾーンへ動かす。1¢）
   - 補給（4¢でカードを1枚引く。1ターン1回。引いたカードは次のターンから使える）
   - キルストリークを使う（SPを消費）。**UAVだけは予約ではなく、押した瞬間に発動**して相手の手札が見える
2. **公開**: 両者の行動が一斉に明かされ、次の順で処理される。
   1. 補給のドロー、ローテ（移動）
   2. オペレーターの配置と、その配置時効果
   3. 装備の付与
   4. 戦術とストリーク（**スピード**の小さい順。同じならそのターンのイニシアチブを持つ側から）
   5. **交戦**: 全ゾーンのオペレーターが、AIMの高い順に1回ずつ撃つ。
   6. ターン終了時の処理（炎・毒・C4・回復）
   7. 得点計算
   8. 戦術核の着弾判定
3. **次のターンへ**: 収入を得て、カードを1枚引く。イニシアチブは毎ターン交代する。

### 2.4 撃ち合いの詳細
- 撃つ相手は、同じゾーンにいる敵のうち **HPが一番低いもの**（トドメを優先）。
  - HPが並んだら、ATKが高いほうを狙う。
  - 敵に【ガード】がいれば、必ず【ガード】を狙う。
  - 狙撃できるユニット（HAWKやAWM装備者など）は例外で、ATKが一番高い敵を狙い、【ガード】を無視する。同じゾーンに敵がいなければ、隣のゾーンの敵を狙う。
- AIMが同じユニット同士は**同時に**撃つので、相討ちが起きる。
- 撃ち合いに乱数はない。何が起きるかは完全に決まっている。
- **HEADSHOT**: HPが満タンの敵を、1発で倒したときに出る。キル報酬が +1¢ 増える。

### 2.5 経済
| 項目 | 値 |
| --- | --- |
| 基本収入 | 1ターン目 3¢、以降1ターンごとに+2（上限11¢） |
| キル報酬 | 1キルごとに +1¢（HEADSHOTならさらに +1¢） |
| ロスボーナス | 支配ゾーンが0で、相手が1つ以上支配していたら、次のターンに +2¢ |
| 持ち越し | 上限 14¢ |
| 補給 | 4¢でカードを1枚引く（1ターン1回。手札が上限なら返金） |

収入だけを増やすと4ターン目以降は手札がボトルネックになり、クレジットが毎ターン余る（旧ルールでは5ターン目以降の余りが毎ターン12〜13¢）。補給はその余りをカードに換える出口。

### 2.6 キルストリーク（SP）
キル1回で SP+1。自分のオペレーターが敵に倒されたターンも SP+1（1ターン1回まで）。SPは消費して次のストリークを使う。

| ストリーク | SP | 効果 |
| --- | --- | --- |
| UAV | 2 | 作戦フェーズ中に即発動。このターンの間、相手の手札が見える（相手には「UAVに見られている」と表示される） |
| 空爆 | 4 | 指定したゾーンにいる敵全員に3ダメージ |
| 戦術核 | 12 | 次のターンの終了時に着弾して勝利。その時点で相手が2ゾーン以上を支配していれば阻止される。最終ターンには使えない |

### 2.7 デッキ
- デッキは30枚（同じカードは2枚まで）。最初の手札は6枚（1ターン目のドローで7枚）で、毎ターン1枚引く。手札の上限は10枚。
- 用意しているデッキは3つ: **RUSH**（速攻）/ **SNIPER**（狙撃と防御）/ **TACTICAL**（ユーティリティとC4）。

## 3. カード

### 3.1 キーワード
【】で書くキーワードは次の7つだけ。覚える言葉を増やさないため、それ以外の能力（狙撃・裏取り・トラップ・回復など）はカードごとに効果をそのまま文章で書く。オペレーターのおよそ1/3がキーワードを持つ。

| キーワード | 効果 |
| --- | --- |
| ガード | 同じゾーンの敵は、このユニットを優先して撃つ |
| 潜伏 | 出したターンは射撃の対象にならない |
| 防弾 | 受けるダメージが1回ごとに-1（最低1） |
| 吸血 | 射撃で与えたダメージ分、自分のHPを回復する |
| 必殺 | このユニットがダメージを与えた敵は即座に破壊される |
| 狂化 | ダメージを受けて生き残るたびATK+1 |
| 絆 | 指定のオペレーターと同じゾーンにいるとき強化される |

### 3.1.1 オペレーターの作り方
- **ステータスはコストに比例して大きくする**（ATK+HPの目安: 1コスト2〜3、2コスト4〜5、3コスト5〜7、4コスト6〜10、5〜6コスト10〜11、7コスト以上は18前後）。AIMは速さの個性として使い、同じコストでも「速くて脆い」「遅くて硬い」をはっきり分ける。狙撃役（HAWK・DEADEYE）や【必殺】のWIDOWのように能力そのものが強いキャラは、あえてステータスを低めにする（HAWKのHPを3に戻すとSNIPERデッキの勝率が62%まで上がった）。
- 効果が似たキャラは、ステータスの形か効果の強さを変えて被らないようにする（例: JOLTはバランス型、PUPはATK3/HP1の使い捨て突入役。SCOUTはドロー、BITは次のターン+2¢）。
- 役割のはっきりした3種類の特別枠を置く。

| 枠 | 4コスト | 7コスト | 9コスト |
| --- | --- | --- | --- |
| スキルが強いがステータスが低い | BEACON 0/4/1（このゾーンを確保すると+1pt） | SALVO 2/4/3（配置時：全ゾーンの敵全員に2ダメージ） | - |
| ステータスが高いがスキルなし | BRUTE 4/6/6 | GOLIATH 7/11/5 | - |
| スキルもステータスも強い | - | - | JUGGERNAUT 6/14/4【ガード】【防弾】【狂化】、HAVOC 5/10/9【吸血】同じゾーンの敵全員を一度に撃つ |

### 3.3 バランス検証（AI同士の自動対戦）
`npm run sim` で、3デッキの全組み合わせをAI（隊長）同士で対戦させて調整した。

| 回 | 変更 | RUSH | SNIPER | TACTICAL |
| --- | --- | --- | --- | --- |
| 1 | 初期値 | 41% | 75% | 34% |
| 2 | 隣接ゾーンへの狙撃はダメージ-1、AWMはATK+3→+2、SGとナイフを強化 | 43% | 80% | 28% |
| 3 | HAWKのATKを4→3、BULWARKのHPを5→4、SCOUTのAIMを7→5、JOLTのHPを2→3 | 49% | 66% | 35% |
| 4 | TACTICALの低火力ユニットのATKを+1、SNIPERデッキの精密射撃とAWMを1枚ずつ減らす | 36% | 65% | 49% |
| 5 | 【裏取り】にガード無視を追加、TITANのHPを8→7 | 46% | 63% | 42% |
| 6 | HAWKのHPを3→2、DEADEYEのATKを6→5（**確定**） | 51% | 51% | 48% |
| - | 確定値で540試合を再計測 | 55% | 48% | 48% |

※勝率はミラーマッチを除いたもの。1回あたりの試合数は、第1〜4回が180試合、第5〜6回が270試合。

最終値での指標:
- **平均ターン数**: 5.8（1試合およそ4〜5分）
- **イニシアチブの影響**: 最初にイニシアチブを持っていた側の勝率は49%で、有利不利はない
- **キル**: 1試合あたり7.1キル、そのうちHEADSHOTは41%
- **C4**: 爆発は1試合あたり0.40回、解除は0.32回
- **戦術核での決着**: 0.4%（ほぼ起きない＝見せ場として機能する）
- **相性**: RUSH→TACTICAL（61%）、TACTICAL→SNIPER（57%）、SNIPER→RUSH（52%）の三すくみ

#### 第2期調整（経済・キルストリーク・マッチポイント）
10点先取・収入+2/ターン・30枚デッキへの変更後に計測すると、次の3点が機能していなかった。
- **経済**: 4ターン目で96%の場面が手札を全部出せる状態になり、5ターン目以降は毎ターン12〜13¢が余った。ボトルネックが手札に移り、後半は1ターン1枚しか出せず、1ターンのキル数は T3 の2.3から T7 では1.1に落ちた。収入を下げるだけ（上限8¢）でも後半の手札切れと逆転率は変わらなかった。
- **キルストリーク**: 片方がUAVを使わなくても勝率は変わらず（AIM+2が効いていない）、戦術核は約1%。SP入手を増やすだけだと、即勝利の核が31%に跳ねた。
- **終盤**: どのターン時点でもリード側の勝率は72〜78%でほぼ一定。7ターン目の2倍は「リード側のゴールを早める」だけだった。

対策として、補給（4¢で1枚）、収入上限11¢・持ち越し14¢、被キルSP、UAVの即時手札公開、戦術核の予告型化（12SP）、マッチポイント（相手8pt以上で負けている側は確保ゾーン1つにつき+1pt）を入れた。あわせて AWM（AIM-1を削除）、ヘビーアーマー（HP+3→+4）、エコラウンド（+3¢→+5¢）を強化し、バンシー（ATK3→2）とミミック（コスト3→4）を弱めた。

変更前と同じシードで540試合ずつ比較（隊長同士、ミラーを除く）:

| 指標 | 変更前 | 変更後 |
| --- | --- | --- |
| デッキ勝率 RUSH / SNIPER / TACTICAL | 52% / 50% / 48% | 51% / 52% / 47% |
| 3ターン目に2点差以上リードした側の勝率 | 78% | 64% |
| 3点差以上から逆転した割合 | 9% | 22% |
| 4〜6ターン目時点のリード側の勝率 | 77〜78% | 63〜64% |
| 1試合のキル数 | 10.4 | 14.7 |
| 平均ターン数 | 6.6 | 7.1 |
| 戦術核での決着 | 3%（即勝利） | 7%（起動の21%は阻止） |
| 最初にイニシアチブを持った側の勝率 | 46% | 49% |

マッチポイントを「支配点2倍」にすると、7ターン目以降の2倍と重なって4倍になり、8ターン目時点のリード側勝率が29%まで落ちた（リードしていると不利）。そのため「+1pt」にしている。

#### 第3期調整（カード整理）
【】キーワードを7つに絞り、ステータスをコスト順に整え、特別枠の6体（BEACON / BRUTE / SALVO / GOLIATH / JUGGERNAUT / HAVOC）を追加した。同じシードで540試合ずつ比較（隊長同士、ミラーを除く）:

| 回 | 変更 | RUSH | SNIPER | TACTICAL |
| --- | --- | --- | --- | --- |
| - | 変更前 | 52% | 50% | 47% |
| 1 | 整理後の初期値（HAWK 3/3/4、DEADEYE 5/5/6 など） | 43% | 62% | 45% |
| 2 | HAWKを3/2/4に戻す、DEADEYE 5/4/6、GHOST 3/3/6（**確定**） | 49% | 53% | 48% |

新カードは、各プリセットデッキの中コスト2枚と入れ替えて3デッキと108試合ずつ対戦させた。比較用のROOKIEは43%、REAPER・ACEは68%。新カードは BEACON 57% / BRUTE 64% / SALVO 69% / GOLIATH 65% / JUGGERNAUT 62% / HAVOC 64% で、既存の強いカードと同じ範囲に収まった。

| 難易度 | 思考 | 勝率 |
| --- | --- | --- |
| 新兵（easy） | 候補手6つからほぼランダムに選ぶ | - |

## 4. UX／画面

縦画面・片手操作が前提。
- **タイトル**: ランク（RP）、CPU戦、オンライン対戦、遊び方、デッキ。
- **対戦画面**: 上から「相手のHUD → ゾーンヘッダー → 相手の陣地 → 支配バー → 自分の陣地 → 自分のHUD（¢/SP/ストリーク）→ 手札 → READYボタン」の順。
  - 手札のカードをタップすると、置ける場所が光る。そこをタップすれば予約完了。予約した行動はタップで取り消せる。
  - 自分のユニットをタップすると詳細が開き、ローテ（移動）もそこから選べる。
  - 公開したあとは演出を順番に再生する: 相手のカードをめくる → 戦術のエフェクト → AIM順の射撃（弾道・ダメージ表示・キルフィード）→ 支配の表示。
- **エモート**: 「ナイス」「GG」「読み勝ち」「まだまだ」「😱」など。煽りにならない定型文だけにする。
- **効果音と振動**: 銃声、HEADSHOTの金属音、爆発音をWeb Audioで合成する。スマホでは振動も入れる。

## 5. 長く遊んでもらう仕組み（リリース版）
- **ランクマッチ**: ルーキー → ブロンズ → シルバー → ゴールド → プラチナ → ダイヤ → マスター → レジェンド。シーズンごとにリセットする。
- **デイリーミッション**: 「HEADSHOTを3回」「C4を爆破させる」「NUKEを撃つ」など。
- **カード収集**: パック、または直接交換。Snapのように「強さはすぐ揃うが、全種類を集めるには時間がかかる」設計にする。
- **シーズン**: 2〜4週間ごとに、新しいオペレーター・新しいゾーン効果・期間限定ルールを追加する（例: 全員ナイフ、戦術核が6SP）。

## 6. 収益化（課金で強くならない）
- **バトルパス**（無料ルートと有料ルート）: スキン、エモート、キル演出、カードの枠やホログラム。
- **スキン**: オペレーターのスキン、武器の迷彩、HEADSHOTやNUKEの演出の差し替え。
- **広告**: 任意視聴のみ（報酬が2倍になる程度）。
- 強さに影響するものは有料にしない。競技性を重んじる層の信頼を損なうため。

## 7. 技術構成

```
src/engine   純TypeScriptのゲームロジック（DOMに依存しない。決定的。状態はシリアライズできる）
  types / cards / zones / state / plan（作戦の検証）/ resolve（ターン解決とイベント生成）/ ai / view（非公開情報を隠す）
src/app      React UI（Vite）。イベントのスナップショットを順番に再生して演出する
server/      Node + ws のオンライン対戦サーバー（サーバーが正。ルームコード／ランダムマッチ）
scripts/     AI同士の自動対戦によるバランス検証
```

- **サーバーが正**: 両者の作戦はサーバーに集まり、解決もサーバーで行う。クライアントには、それぞれのプレイヤー向けに非公開情報を隠したビュー（相手の手札の中身や山札の順番は送らない）とイベントだけを返す。これでチートを防ぐ。
- **スマホ化**: `npm run build` → `npx cap add android/ios` → `npx cap sync` でストア提出用のプロジェクトができる（手順は README に記載）。本番のサーバーは Fly.io や Cloudflare（Durable Objects）などにデプロイする想定。
